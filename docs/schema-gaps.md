# Schema v1 gaps

Schema v1 is enough to run the chat end to end. These nine points are either undefined or ambiguous. Each lists what the client does today and what we propose. Resolving them is a backend decision; the client already handles each one.

| #   | Gap                                                                                                                                | What the client does today                                                                                                                                                                           | Proposal                                                                                                                                                 |
| --- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Block vocabulary.** v1 names `type` and `category` but defines no values or payloads, and `checkpoint.requires` has no shape.    | Ships parsers for the 12 blocks in [block-contracts.md](block-contracts.md), with aliases.                                                                                                           | Adopt block-contracts.md as schema v1.1.                                                                                                                 |
| 2   | **HITL state in history.** Row 3 doesn't say how checkpoints and decisions come back.                                              | Reads `checkpoint` on the block and `type: "hitl"` user messages (see [backend-contract.md §5](backend-contract.md#5-history-and-hitl)). Keeps decisions made in the session if a reload lacks them. | Return both, so a paused chat reloads with a live card.                                                                                                  |
| 3   | **Resume message id.** Does a resume continue the paused `message_id` or start a new one?                                          | Handles both. The same id continues the message; a new id adds one.                                                                                                                                  | Continue the same `message_id`, so one answer stays one message.                                                                                         |
| 4   | **Archiving.** The glossary says `archived` changes via row 4, but the PATCH body doesn't list it.                                 | Sends `{ "archived": true                                                                                                                                                                            | false }` through row 4.                                                                                                                                  | Add `archived` to the row 4 body. |
| 5   | **Selected model.** Row 1 returns a catalog and row 4 sets one model, but row 3 doesn't return it and row 6 has no per-turn model. | Remembers the choice locally and PATCHes the conversation.                                                                                                                                           | Return `model` on rows 2–3, and optionally accept it on row 6.                                                                                           |
| 6   | **Scope catalog.** Nothing lists the workspaces and workflows the composer's picker offers. `Source` has no label either.          | The host app passes `scope.groups`.                                                                                                                                                                  | Add `GET /v1/scope` (workspaces → workflows with labels), and a `label` on `Source`.                                                                     |
| 7   | **Uploads.** Row 6 takes `attachments[]`, but no endpoint produces them.                                                           | The host app provides `attachments.upload(file)`.                                                                                                                                                    | Keep uploads with each product's file service, or add a shared presigned-upload endpoint.                                                                |
| 8   | **Non-streamed replies and errors.** The `stream: false` response shape and the non-2xx error body are unspecified.                | Always streams. Converts a JSON reply if one arrives. Reads `message` or `detail` from errors.                                                                                                       | Specify the `stream: false` reply as `{ message: { message_id, content[], stop_reason }, title }`, and errors as `{ error_type, message, retry_after }`. |
| 9   | **Reconnect.** A dropped stream can't be resumed.                                                                                  | Marks the answer interrupted, offers Try again, and refetches on the next open.                                                                                                                      | Accept `Last-Event-ID` on a `GET …/messages/{id}/stream` to resume in-flight turns.                                                                      |
